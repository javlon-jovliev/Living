# Living — qiymat, foydalanuvchi va bozor gipotezalari

**Status:** Hypotheses; primary market research hali o'tkazilmagan.

## Potensial qiymat

Mumkin bo‘lgan foyda **UI erkinligi**ning o‘zida emas, balki:
1. turli vosita va ma'lumotlarni bitta kontekstda ishlatish;
2. ilgari mavjud bo‘lmagan, vazifaga mos funksiyani bevosita yaratish;
3. yaratgan vositani saqlash va qayta ishlatish;
4. o‘z ish oqimini platformaning oldindan belgilangan rejimlariga moslashtirishga majbur bo‘lmaslikda.

## Kimga foydali bo‘lishi mumkin?

| Segment (gipoteza) | Muammo | Test uchun vazifa |
|---|---|---|
| Tadqiqotchilar | Manba, timeline, izoh, tasvirlarni ajratilgan ilovalarda tutish | Maqola + timeline + izohni birlashtirish |
| Analitiklar | Ko‘p data source va noodatiy visualizations | Expenses + calendar → temporal analytics |
| Operations / PM | Status, task, risk monitoring vositalari ajratilgan | Task + deadline → risk object |
| Creative technical users | Mos kelmaydigan workflowlar | Media + metadata → custom tool |
| Mass-market user | Erkinlik ehtiyoji noma'lum | Tayyor UI vs malleable UI takliflari |

## Qarshi dalillar

- Customization uchun qo‘shimcha vaqt sarflanadi.
- Foydalanuvchi UI yasashni emas, vazifani tugatishni xohlaydi.
- Bir-biridan juda farqli personal space jamoada ishni murakkablashtiradi.
- Kompozitsiya xatolari zararli yoki tushunarsiz natijaga olib keladi.
- Yangi OS ecosystem compatibility va migration muammolariga duch keladi.

## Raqobatni to‘g‘ri o‘qish

Visual builder, low-code/no-code, AI app generator, spreadsheet, plugin ecosystem va automation vositalari *qisman o‘xshash ehtiyojlarni* qondiradi. Ularning mashhurligi Living'ning universal OS bozorini isbotlamaydi. Real raqobat “buni yangi Living obyekt bilan yaratish” va “mavjud app'da oddiy qilish” o‘rtasida.

## Ishni boshlash uchun validatsiya

1. Segment bilan suhbat: real muammo, hozirgi vosita, vaqt/xato xarajati.
2. Baseline task: Living bo‘lmasdan o‘sha natijaga qanday erishadi?
3. Prototype task: Living yaratgan natija bilan solishtirish.
4. Repeat usage: obyekt 7–14 kunda yana ishlatiladimi?
5. Willingness to pay: suhbatdagi deklarativ xohish emas, real xarid yoki jiddiy intent signal.

## Muvofiq bo‘lishi mumkin bo‘lgan biznes modellar

- Open-core runtime + pullik collaboration/sync;
- Tashkilotlar uchun policy/security va integration layer;
- Professional vertical workspace;
- Developer SDK va keyin ekotizim.

**Bular imkoniyatlar, tasdiqlangan strategiya emas.** Living'dan pul topish mumkinligini aniq aytish uchun to‘lovga tayyorlik va mahsulot qiymati bo‘yicha tadqiqot kerak.
